# ソブリン4/20 — Android自動操作・第一波プロトタイプ

## 推奨：元ゲームを改造しない時刻同期（APK解析の結果）

**ゲーム本体のパッチは必須ではありません。** 元の APK を変更する v0.4 engine-bridge は実験的な別ルートであり、通常の遊び方では使用しません。

ゲーム内には二つの「12 AM」があります。

- ナイト開始の演出画面（`05-what day`、CCNフレーム4）の時計表示 `time.Active` は (646,285) に配置。この段階では4.97秒の移動判定は動いていません。
- 警備室（`06-Main Room`、フレーム5）の右上の時計は `time of day` (1185,59)、`am` (1198,31)。メインルームのフレーム開始直後から表示されます。

フレーム4のソースイベントでは、`night.Active` の値を**毎ゲーム更新で+1**し、値が**130を超えたら** `Fade` の半透明値を255へ設定してフェードを始めます。 `Fade` の値は毎更新で**4.25ずつ減る**。60FPSなので、単純に131更新と60更新で **約191更新＝3.183秒**（演出フレーム開始→警備室開始）の名目値です。遷移1フレームなどの実行境界でズレる余地はあります。

したがって未改造で厳密化するなら、いずれか：

1. **メインルーム右上の「12 AM」の出現**をゲーム開始の観測点とする。この時計はメインルーム開始時から存在するため、遅延は描画・キャプチャ由来の短い差に絞れる。検出は開始時1回だけ、敵の認識は不要。
2. **演出画面の「12 AM」出現**を観測して約3.183秒を加えた時刻をゲーム開始の予測点とする。時計の白画素が光るだけの検出より専用の画像パターン検出が望ましい。
3. 開始ボタンREADYの操作自体をコントローラから入力し、READY→演出フレーム開始の表示遅延を1回校正し、その後は全時刻を絶対時刻で管理。

元ゲーム改造に不安がある場合は **1を優先、あるいは2を一度校正して固定遅延化**。以前の v0.3 の大ざっぱな白画素閾値は検出実験であり、ゲーム内同期の精度が保証されたものではありません。4/20の移動タイミングに使う前に、検出位相の誤差を調べます。



FNaF 1 Android版の **最初の約5秒の操作** を検証する試作アプリです。GitHub ActionsでデバッグAPKをビルドできます。

**ビルド成功:** [GitHub Actions #2（2026-10-10 JST）](https://github.com/tara-sooo/FNaF/actions/runs/37969133141) — `SovereignFirstWave-debug-apk` に `app-debug.apk` を保存済み。

## APKを入手する

1. [成功済みActions実行](https://github.com/tara-sooo/FNaF/actions/runs/37969133141)を開く。
2. ページ下部の **Artifacts → SovereignFirstWave-debug-apk** を選択。
3. ダウンロードしたZIPを展開し、`app-debug.apk` をAndroidへインストールする。

今後の再ビルドは **Actions → Build Android debug APK → Run workflow** で実行できます。ソースを変更してmainへプッシュした場合も自動ビルドされます。

## v0.3：FNaF 1 の時計に同期して開始（画面共有）

**GitHub Actionsでビルド成功:** [v0.3 Clock Sync ビルド](https://github.com/tara-sooo/FNaF/actions/runs/37972622407)、Artifact `SovereignFirstWave-debug-apk`。完成APKは `app-debug.apk` です。v0.3の `versionName` は `0.3-clock-sync-test`。

これまでの音量＋や5秒後の手動実行は残しています。新しく**12 AMの表示を検知して最初の9ジェスチャーを自動開始**する機能を追加しました。APKメイン画面の時計表示オブジェクト位置（約X=1185、Y=59）を参照し、Android MediaProjectionの連続画面フレームから右上の小領域だけを検査します。ゲーム画像・敵の姿は保存せず、認識にも利用しません。

### 初回の実行

1. v0.3 `app-debug.apk` をインストールします。過去のActionsビルドと署名が違って更新失敗する場合、旧アプリのアンインストールが必要です。
2. Androidアクセシビリティサービスを有効化し、アプリ内で「サービス：接続済み」と「実行を許可ON」を確認します。
3. **FNaFのCustom Nightをまだ開始していない状態**で、アプリ画面の **⑤ 12 AMの出現を検出して自動開始（画面共有）** を押します。
4. Androidの画面共有の許可画面で、可能なら **画面全体を共有** を選びます。「単一アプリのみ共有」を選ぶと操作器側が撮影される場合があります。
5. FNaFへ切り替えて、Night7 4/20を開始します。画面右上の「12 AM」が出現した瞬間を検出すると、**約1.15秒から始まる改訂9操作**をゲーム時計基準で実行します（CAM 4B選択→フォクシー対策→左右ドア閉鎖）。
6. アプリへ戻り **動作状態を更新** のログを見ます。`[CLOCK]`の検出ログおよび「ゲーム時計同期・最初の9操作」があれば同期・操作送信が成立しています。

`12 AM`が40秒以内に検出できない、誤検出する、あるいはゲーム内操作が始まらない場合はログを共有してください。時計判定領域の輝度条件を端末映像に合わせて修正します。

**精度について：** これはゲームのメモリ内の時計値を読む方式ではありません。時計が画面に描画されてからキャプチャフレームに届くまでの遅れがあるため、この初版のままゲーム内部0秒への厳密一致を保証するものではありません。以後の `1 AM` 等の時計表示変化と元の90秒刻みを比較し、位相誤差を記録します。最初の9操作以外の540秒制御はまだ実装していません。

## v0.2：音量＋が効かないとき

[v0.2 ビルド成功済み（Actions）](https://github.com/tara-sooo/FNaF/actions/runs/37970774409)。Artifacts の `SovereignFirstWave-debug-apk` から最新版の `app-debug.apk` を取得できます。

旧版をインストール済みなら、GitHub Actionsのデバッグ署名が変わって上書きに失敗することがあります。その場合、**旧版をアンインストールしてから**新版を入れ、アクセシビリティを再度有効にしてください。

1. Android設定で **Sovereign First Wave** アクセシビリティを有効化し、アプリに **サービス：接続済み** と表示されるか確認
2. アプリ内の **実行を許可** をチェック
3. **5秒後にモニターを1回タップ** ボタンを押し、5秒以内にFNaF 1へ切り替える
4. 終了後アプリへ戻り **動作状態を更新** でログを確認する
5. 単発が動けば **5秒後に最初の9操作を開始** で一連の入力を確認する

`dispatchGesture受理` や `完了通知` が出るのにゲームが動かなければ座標設定を調整します。`サービス未接続` ならアクセシビリティの設定、`実行許可OFF` ならチェックを確認します。音量＋キーが届いているかどうかも動作ログに表示されます。

## スマホでの操作

1. `app-debug.apk` をインストールして起動。
2. Androidのアクセシビリティ設定で **Sovereign First Wave** を有効にする。Android 13以降で制限された設定と表示されたら、アプリ情報画面から明示的に許可する。
3. アプリ内でタップ座標と画面矩形を設定・保存し、`音量＋で実行を許可` をオンにする。
4. FNaF 1の警備室へ移動して、**音量＋**を押すと一連の操作を開始する。**音量−**で中断する。

`音量＋` を押した時刻を0秒としています。**ゲーム内部の開始タイマーと自動同期するわけではありません。** 初回の位置合わせ・入力確認用途で使ってください。
